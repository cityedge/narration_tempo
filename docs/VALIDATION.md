# 検証記録

過去の検証コマンドにはEMSワークスペースから実行したパスを記載しています。現在の公開用フォルダでは `npm test` を使用します。

## 区間プレビュー修正版の確認結果（2026-10-22）

- 原因：プレビューも全体変換用のラウドネス計測を呼び出し、さらに冒頭から選択区間まで速度変換していました。計測結果で全体波形を更新しながら、全体の処理後音声を保持しない不整合もありました。
- プレビューを専用の区間処理へ分離。全体波形と測定値は、全体変換が完了した場合だけ更新するよう変更しました。
- DSP回帰テスト：60分相当の音源の30秒地点と50分地点で、EQ OFF／3種類ONのプレビューを検証。前後12秒の範囲外を読み込もうとすると即失敗する音源を使い、全体走査・冒頭からの再処理がないことを確認。全体変換済みの切り出しは保持音声のFloat32 PCMとバイト一致しました。
- ブラウザ回帰テスト：プレビュー後も全体波形・全体測定値が変わらず、全体変換前の処理後再生／保存は無効のまま。下のBで区間再生でき、全体変換後のプレビューは既存結果と保存状態を保持することを確認。
- `node Narration_Tempo/test.mjs --preview-long`：45分・48 kHz・モノラルの合成WAVで、16分48秒地点／EQ OFFは245 ms、40分地点／EQ3種類ONは490 msでプレビュー作成。音源読み込み完了後のテストPCでの計測値で、利用環境によって異なります。原音は259 MB、プレビュー操作による全体波形の変化はなく、Bの音声再生も通過しました。

## 上部ステータス・72分上限版の確認結果（参考、2026-10-22）

- 上部のドロップ欄／ステータス欄を約30%／70%で配置。1366×768の基本画面は1画面に収まり、390px幅は縦並びで横スクロールなし。長いファイル名は省略表示し、ホバーで全文を確認できます。
- `node Narration_Tempo/test.mjs --limits`：72分・8 kHz・モノラルの合成WAVを読み込み、72分の16bit WAVとして保存できることを確認。72分＋1サンプルの入力、72分1秒の出力指定は開始前に拒否。
- `node Narration_Tempo/test-dsp.mjs`：72分・48 kHz・ステレオが保持容量制限内であること、60分から72分への減速が許可されること、出力1サンプル超過と高サンプルレートの容量超過を拒否することを確認。
- オフラインChromiumで原音／処理後の再生・シーク、WAV／MP3保存、キャンセル、日英表示の既存操作も通過。コンソールエラーなし。検証はHTMLのメモリ読み込みで実施しており、file://直接起動は未確認です。

## 再生・保存分離版の確認結果（参考、2026-10-22）

- 原音の変換前再生、処理後の全体再生、任意位置へのシーク、再生中の原音／処理後切り替え、停止位置への復帰：通過。
- 全体変換でダウンロードしないこと、形式変更で再変換しないこと、設定変更で旧結果を保存できなくなること：通過。
- 緑・赤・グレーの差分波形をピクセルで確認。1366×768ではプレビューと詳細設定を閉じた基本画面が1画面内。390px幅は横スクロールなし。
- 全体変換とMP3保存の中止・再試行、切り替え直後の停止、EQ解析中止後の再変換：通過。
- MP3保存後に再度24bit WAVを保存し、元の24bit WAVとバイト一致（保持音声の変更なし）。MP3を再デコードして長さ・チャンネル・音声の存在を確認。
- 96 kHz入力のMP3出力と、WAV出力時の96 kHz維持：通過。
- 16bit TPDFの無音出力で±1 LSB、平均ほぼ0、分散約0.25 LSB²を確認。Float32保持音声は元のFloat32と一致。
- EQの各補正量、ステレオ独立性、区間境界とランダム読み戻しを独立した連続フィルター計算と比較：通過。
- 60分・48 kHz・ステレオ入力を1.300倍に変換し、終盤へシークして再生、24bit WAV保存：通過。46分9.231秒・797,538,506バイト。読み込みから保存まで約59.6秒。
- 同じ保持音声から長尺MP3保存：通過。48 kHz・ステレオ、46分9.264秒・28,467,960バイト。MP3エンコード約181.7秒。合成音源とテストPCでの値であり、実音声・利用環境によって変わります。
- `node Narration_Tempo/test-dsp.mjs`、`node Narration_Tempo/test.mjs --mp3`、`node Narration_Tempo/test.mjs --long --long-mp3` で検証。UI検証はネットワーク遮断したChromiumへHTML文字列を読み込んで実施しました。Browser plugin not available。アプリ内ブラウザのfile://制限により直接ファイル起動は未確認です。ローカルサーバーは使用していません。

## 初版の確認結果（参考、2026-10-22）

- WAV読み込み、レベリング、目標時間、16/24bit保存、ステレオ48 kHz、末尾プレビュー、A/B再生位置対応、日英、無効WSOLA、取消と再試行：通過。
- WSOLA単体：8秒合成音源・モノラル／ステレオ・0.700/1.000/1.150/1.300倍の24bit PCMが旧MVPとバイト単位で一致。
- 45秒合成音源：前半・後半のレベル差を3 dB未満へ低減。出力サンプルピークは−1 dBFS以下。
- VBR MP3から24bit WAVへの変換：通過。
- 60分・48 kHz・ステレオPCM16 WAVから、1.300倍・24bit WAVのダウンロード：通過。出力46分9.231秒、797,538,506バイト。テスト環境で読み込み・解析から保存まで約41.5秒。実音声の音質や他環境の速度を保証する値ではありません。
- 60分入力を0.700倍にして出力上限を超える指定：開始前に禁止。
- 1366×768で基本操作が1画面に収まり、390px幅では横スクロールなし。詳細設定展開時と狭い画面では縦スクロールします。
- 画面のタイトル、構成、文字、配色、余白、操作ボタンをデザイン案と画像比較。再生UIはブラウザ標準部品、波形は実データのため概念図とは異なります。
- アプリ内ブラウザのURLポリシーでfile://が禁止されているため、検証は独立ChromiumへHTMLをメモリ読み込みして実施。直接起動そのものはこの環境では未確認です。サーバーや外部リソース要求はありません。

提供済みのMVP、引き継ぎ書、初期EMS HTMLは変更していません。実際のナレーションを使った最終的な聴感評価は利用環境で行ってください。
